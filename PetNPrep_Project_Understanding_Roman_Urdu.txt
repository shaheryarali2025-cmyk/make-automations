============================================================
1. YE PROJECT KYA THA?
============================================================

Ye project PetNPrep business ke complete customer journey, automation,
data storage, portal support aur chatbot support ko improve karne se related tha.

PetNPrep ka main product Pet Protection Plan (PPP) hai. Iska purpose pet owner
ki pet-care instructions, pet details, medical information, feeding routine,
veterinarian information, caretakers aur emergency wishes ko organized form
mein collect karna aur completed documents/PDFs Pet Care Portal mein provide
karna hai.

Project ka kaam sirf chatbot banana nahi tha. Ismein website, checkout,
SuiteDash portal, Make.com workflows, Airtable records, Stripe billing,
Pet Profile Reports, emails aur QA bugs sab connected thay.

4. SYSTEM ARCHITECTURE - SIMPLE FLOW
============================================================

General PetNPrep information:
Customer Question -> Chatbase Knowledge Sources -> Chatbase Answer

Customer-specific live information:
Customer Question -> Chatbase Lookup Action -> Make.com API Router
-> Stripe / Airtable / SuiteDash -> Current Result -> Chatbase Answer

Pet Protection Plan data:
SuiteDash/Form Submission -> Make.com Webhook -> Airtable Search
-> Airtable PPP Record

Pet Profile data:
Pet Profile Submission -> Make.com Webhook -> Pet 1-16 Route
-> Airtable Pet Profile Report Record -> Link with PPP Record


============================================================
5. WORKFLOW 1 - PET PROTECTION PLAN (PPP)
============================================================

Make.com mein dedicated "Pet Protection Plan (PPP)" scenario banaya gaya.

Basic flow:
1. Custom Webhook Pet Protection Plan submission receive karta hai.
2. Incoming fields ko Airtable mapping ke mutabiq prepare kiya jata hai.
3. Airtable Search Records existing matching submission/plan check karta hai.
4. Filters decide karte hain ke new record create hona chahiye ya nahi.
5. Airtable Create a Record PPP table mein plan-level record create karta hai.

Airtable PPP table ke important fields:
- Submission ID
- PPP Number
- Pet Count
- Linked Pet Profile Report records
- Owner/customer information

Is workflow ka purpose:
- Plan submission ko traceable banana.
- Duplicate plan records ka risk kam karna.
- Plan-level data ko pet-level data se separate rakhna.
- PPP ko related Pet Profile Reports ke saath link karna.


============================================================
6. WORKFLOW 2 - PET PROFILE REPORT (PPR)
============================================================

PPR ka matlab "Pet Profile Report" hai.

Make.com mein dedicated "Pet Profile Report (PPR)" scenario banaya gaya.
Ye workflow Pet 1 se Pet 16 tak individual mappings handle karta hai.

Basic flow:
1. Pet Profile submission webhook par receive hoti hai.
2. Scenario related PPP aur submitted pet slot identify karta hai.
3. Router Pet 1 se Pet 16 mein se correct route select karta hai.
4. Correct Airtable module pet-specific record create/save karta hai.
5. Pet Profile Report record related PPP record se link hota hai.

Pet Profile Report table mein detailed pet fields rakhe gaye, jaise:
- Pet identity/details
- Medical information
- Daily routine
- Behavioral information
- Training Level / Training Details
- Favorite Toys
- Favorite Treats
- Favorite Activities
- Emergency veterinary information
- Age/AgeText aur other mapped pet fields

Why 16 separate paths?
- Har supported pet slot ka apna SuiteDash custom-field set tha.
- Generic mapping se wrong pet field ya missing data ka risk tha.
- Dedicated Pet 1-16 mappings se correct pet ka data correct record/report mein
  bhejna possible hua.


============================================================
7. CHATBOT API ROUTER WORKFLOW
============================================================

Make.com mein "PetNPrep Chatbot API Router" scenario banaya gaya.
Chatbase ka active custom action "Lookup customer account" is scenario ko API
ya webhook ke through call karta hai.

Chatbase action Make.com ko ye values bhejta hai:
- query: customer ka original unresolved question
- email: primary lookup identifier
- name: agar available ho

Important behavior:
- Har new customer-specific question par fresh action call hota hai.
- Previous lookup result par rely nahi karna.
- Agar email/name conversation mein already mil chuka hai to dobara nahi poochna.
- Agar chatbot email maange aur next reply sirf email ho, to original question
  preserve karna hai. Email-only message ko query nahi banana.
- Make.com actual question dekh kar correct source choose karta hai.
- Customer ko backend system ka naam nahi batana.
- API response ke bina customer-specific data guess nahi karna.
- Result incomplete ho to clearly kehna ke current account data se requested
  information confirm nahi ho saki.

Routing rules:

Stripe:
- Charges
- Payments
- Invoices
- Receipts
- Refunds
- Recurring billing
- Subscription billing
- Next charge / next billing date
- Payment history

Airtable:
- Customer type
- Subscriber record
- Product/product access
- PPP record/details
- PPD status and dates
- Saved plan information
- Other stored customer records

SuiteDash:
- Portal login
- Portal access
- Portal invitation
- Documents and PDFs
- Downloads
- Missing portal files
- Account/portal file access

Chatbase Knowledge Base only:
- General product questions
- General pricing/process questions
- Educational questions
- Non-account-specific PetNPrep information
